# Qwen3.5 根拠解釈と理由付き発言の検証

## 現在の判断

Qwen3.5-4B-4bitで、根拠の否定・未確認を保つ実験プロンプトと、本人の理由・専門観点を全文rendererへ渡す経路を追加した。
`--prompt-profile source_grounded`を明示した場合だけ有効で、既定の`orthogonal_fewshot`や既存本文Weightを置き換えていない。
今回追加したのは推論入力の改善であり、新しいLoRA Weightを学習したという意味ではない。

旧題材の一部の誤読とID失格は改善したが、新題材の比較方向・対象の取り違えは残った。
理由付き入力だけでは全文発言の合格は増えず、JSON外形の失敗が多かった。
出力JSONの具体形を追加した実生成も完了し、最上位objectの外形は9/9になった。
行キーと全IDを含む完全なJSON契約は8/9で、1件の行キー違反が残る。
ただし直接の全文発言は0/24、補正後7/24で、意味の誤りや代替文への依存が残る。
自然な自由討論、源データの意味保持、General Weightの完成はまだ確認できていない。

## 変更した経路

独立主張・すり合わせ・投票修復に、否定、条件、対象範囲、未確認状態を保つ共通の指示を追加した。
未算定を不要、未実測を確認済みの優劣へ読み替えないことを明記し、D番号の存在だけを根拠の正しさと扱わない。
旧プロンプト4種類のsystemは変更せず、本文rendererにはこの判断用指示を混ぜない。

全文rendererでは、同じ本人の`candidate_reason`、その出自、既存のworldview・utility・lossを追加する。
別人格のrawや発言文は渡さない。候補理由は追加の証拠ではなく、原文のevidenceと照合するための候補である。
本文Adapterの経路はclaim本文だけを生成するため、この理由入力を使わない。
既存のID、語数、根拠数値、move、凍結claimの検査を緩めていない。

## 根拠判断の実生成

旧Swift／Rust題材は8人格を両プロンプトで再生成した。
新規の手押し／電動搬送と短時間外出／雨具には、未確認と確認済みの対照を用意した。
各新規条件は4人格で、2分野を通じて8人格全員を含む。同じ分野の正負対照は同じ人格・候補順序を使う。
根拠IDは旧題材のD05/D06から変更し、候補順序も人格ごとに逆転している。
モデルへ採点条件や答えは渡さず、これらの診断例をSFTの正解へ戻さない。

全10実行、48のBase呼び出しを完走した。
以下は全ての初期主張を対象とした契約検査であり、公開event上位だけの合格率ではない。

| 題材 | 従来 主張／発言契約 | 根拠忠実 主張／発言契約 |
| --- | --- | --- |
| 旧設計題材 | 主張15/16、発言13/16 | 主張16/16、発言14/16 |
| 搬送 未確認 | 主張8/8、発言7/8 | 主張8/8、発言6/8 |
| 搬送 確認済み | 主張8/8、発言6/8 | 主張8/8、発言4/8 |
| 雨具 不確定 | 主張8/8、発言7/8 | 主張8/8、発言7/8 |
| 雨具 固定条件 | 1人格のJSON失敗、残る主張6/6・発言4/6 | 主張8/8、発言7/8 |

旧設計題材のID失格は1件から0件になった。
しかし「SwiftUI利用の安全性は確認済み」「UIの実測が未完了」等、源データの測定対象を取り違える発言は残る。
追加指示で発言の引用契約が後退した条件もあるため、この表を精度向上や昇格の証明には使わない。

確認済みの搬送では、電動が手押しより7dB静かな原文を「7dB高い音」と逆転する発言があった。
また、電動の費用0円や騒音の利点を手押し案の属性として述べる例も残る。
雨具の固定条件でも、比較実験が済んだデータを結果不足とする発言があり、確認済みを一律に保留へ戻すだけでは正しくない。
従来の雨具固定条件では、一人格が文を反復して600token上限でJSONを完結できなかった。失敗人格を分母から隠していない。

これらは保存rawの列挙例の確認であり、一般の意味を自動判定する新しいverifierを実装したものではない。
引用、否定、比較方向、対象、限定条件、正確な言及と単なる省略を分ける必要がある。

## 全文発言の8人格比較

根拠忠実プロンプトを両条件で固定し、旧renderer入力と、本人の理由・観点付き入力を比較した。
Base、seed20261005、temperature0、24event上限、2回すり合わせ上限、全てAdapterなしで実行した。
両条件とも16eventと8人の投票を終え、1回のすり合わせでSwift案に合意した。

| 入力 | 時間 | model call | 直接の全文生成 | 補正後 | 代替文 | 最上位object失敗batch |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 旧入力 | 311.196秒 | 25 | 0/24 | 1/24 | 23/24 | 8/9 |
| 本人の理由・観点付き | 382.993秒 | 25 | 0/24 | 1/24 | 23/24 | 7/9 |

独立判断raw8/8、投票raw8/8、最終選択が一致し、判断・投票のAdapterは全てNoneだった。
全文rendererの24入力では、旧入力に本人の理由と設定済み専門観点だけが加わったことを照合した。
これはこの固定fixtureの構造確認であり、全将来入力での分離や意味の非回帰を証明するものではない。

schema失敗の多くは、`{"utterances":[...]}`を要求したのに配列だけを返すものだった。
モデルのJSONを後から包んで直接成功とは数えない。
実験プロンプトへJSONの具体形を追加した条件を別に凍結し、同じBaseで実生成した。
候補理由のD番号付きコピーも残り、理由入力だけで自然な会話になるとは確認できなかった。

JSON明記条件は353.942秒、25呼び出しで完走した。
同じ理由・観点付き入力を使い、独立判断raw8/8・投票raw8/8も同一だった。
9batch全てが最上位objectの外形を満たしたが、行キーと全IDを含む完全な契約は8/9だった。
無補正の全文生成0/24、補正後7/24、代替17/24で、完全な発話契約の成功ではない。
投票8発言の全文renderer成功は0で、すり合わせの表示は依然として代替文だった。
補正後の採用例にも「UI実測未完了」の誤読や、D番号を消した後の「の解析部分」という不自然な文が残った。
外形の改善と意味・自然さの改善を混同せず、Whole gateは不合格のままである。

次の学習対象は、この理由・観点・evidence付き入力に対応する全文utterance rendererである。
判断へLoRAを混ぜず、実験入力のtoken境界、JSON契約、選択保持、源データの対象と状態、反復しない自然な発言を、
別の学習／開発／未学習題材に分けて検証する必要がある。現在の診断の答えを学習へ戻さない。

## 運用と保存先

既定のCLIは変更していない。実験指定は次のように行う。

```sh
<mlx-python> cod_model.py event-debate \
  --domain general --backend mlx --model-path /path/to/Qwen3.5-4B-4bit \
  --ledger /path/to/claim_ledger.json --prompt-profile source_grounded \
  --max-turns 24 --reconcile-rounds 2 --portable-context --out /path/to/new-run
```

20GiB・2秒の容量監視付きの実験runner、モデル、監査出力は外付けに置いた。
Baseを内蔵へ複製せず、推論を逐次実行した。

```text
audit: /Volumes/data4/cod_model_weight/evaluations/source-grounding-v1_20261006
```

`plan.json`、`fresh_plan.json`、`context_plan.json`、`schema_plan.json`は、それぞれ生成前の条件である。
`decision_audit.json`は失敗人格を含む全主張の検査、`context_comparison.json`は本人入力と判断分離の照合、
`schema_comparison.json`はJSON明記条件、`*_strict_schema_audit.json`は外形と行キー・IDを分ける厳密検査、
`body_guard_replay.json`は旧本文1,173行・22ファイルの同じ採点結果を確認した記録である。
元raw、旧基準、v9の記録は変更していない。

全104単体テストは成功した。これはプロンプトの適用先・本人入力・旧guardを確認するコード検証で、Generalモデルの完成ではない。

[新規対照](../data/general_source_grounding_v1/fresh_cases.json)は実際の天気や工房データではない。
未確認状態・比較対象を正しく扱う学習と、自然な全文発言の学習・新しい未学習例での検証が引き続き必要であり、
この実験だけでGeneral Weightを完成・公開扱いにしない。
