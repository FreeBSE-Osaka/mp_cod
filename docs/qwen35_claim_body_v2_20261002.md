# Qwen3.5-4B Claim Body v2 学習検証 2026年10月2日

## 学習結果

新しい条件保持の教材で2種類のLoRAを学習した。前回版から継続する方式は、
利用資格と別の行動の許可を取り違えるため不採用とした。
BaseからMLPの出力側だけを学習する方式の48ステップ版は、新しい16問の直接合格が
前回版9/16から11/16へ、語尾補正込みで13/16へ改善した。
全文の手動確認では、この16問で条件の意味が変わる例は見つからなかった。

候補のAdapterは754,632 bytes（約0.755MB）。Base本体は約3.03GBで、
AdapterサイズにBaseや実行時メモリは含まれない。
8人の実走でも確認したが、別題材で提案を実行中の事実へ変える本文が出たため、
**研究用HOLD**を維持する。既定Weightの置換やWeight公開は行っていない。

## データと選定

教材は架空の施設利用・記録・日程調整・受渡しの32件。各話者8人に展開した256例と、
前回の凍結trainから固定seedで抽出した復習256例を混ぜ、trainを512例にした。
validは155例、testは251例だが、話者名を変えた複製を独立した事例数とは数えない。
新しく用意した内容は、開発用8問・2topic、最終検証16問・4topic。
最終検証には8話者をそれぞれ2回含めた。

教材・選定規則・意味を変える反例・許容する同義表現は、モデルの生成を見る前に固定した。
「だけ／に限り」や否定形の差を許すが、利用資格を別の行動の許可へ変えることは許さない。
新しい最終検証と前回の12問はtrainとのclaim重複なし。
比較の途中で正解を学習へ戻したり、最終検証の採点規則を緩めたりしていない。

最大tokenはtrain 259、valid 265、test 266。設定384以内で切り詰めはなかった。
学習時のassistant prefixが、`enable_thinking=False`の推論入力と一致した。
system promptは前回と同じで、Base・前回版・候補に同じ入力を与えた。

## 学習方式の比較

| 条件 | 前回版から継続 | BaseからMLPのみ |
|---|---:|---:|
| 学習iteration | 64 | 64 |
| 学習対象 | 最後4層の既定Linear群 | 最後4層のmlp.down_proj |
| trainable parameters | 約1.015M | 約0.188M |
| learning rate | 2e-5 | 1e-4 |
| rankとscale | 4と8 | 4と8 |
| gradient checkpoint | 有効 | 有効 |
| MLX報告peak memory | 5.449GB | 6.029GB |
| 初期validation loss | 0.207 | 0.745 |
| step64 validation loss | 0.071 | 0.082 |

両方ともbatch 1で64ステップまで正常完走。16ステップごとに保存した。
Adapterの小ささと学習時RAMの小ささは同じではない。今回MLPのみの方式は、
trainable parametersは少ないが報告peak memoryは継続方式より大きかった。
lossは8 batchの検証値で、全文の意味正確率とは異なる。

継続方式の全checkpointは、次の主張を取り違えた。

```text
入力: 展示室の利用は招待者に限り資料の撮影は許可しない
誤りの例: 展示室の利用では、招待者以外では資料の撮影を許可しません。
```

元の主張は利用者の限定と撮影禁止を別々に述べるが、誤文は撮影禁止を招待者以外にだけ掛けている。
この方式には最終検証16問を使わず、不採用とした。

MLPのみの16/32ステップ版は、観察区画の入場に関する最初の節で動作を省き、
64ステップ版は展示室の条件を再び取り違えた。48ステップ版は両方の節を明示した。
自動合格が同点でも、意味と文の完全性を満たさない候補は除外し、
48ステップ版を最終生成前に`selection.json`へ固定した。

## 最終生成の比較

| モデル | 新規16問の直接合格 | 語尾補正込み |
|---|---:|---:|
| Qwen3.5-4B Base | 8/16 | 8/16 |
| 前回の本文LoRA v1 step32 | 9/16 | 9/16 |
| MLPのみ v2 step48 | 11/16 | 13/16 |

3モデルともstrict JSONは16/16。
前回版には、録音/映像の保存禁止を肯定へ反転する例、利用者の資格を別の行動の許可へ移す例があった。
候補の16本文を凍結した主張と突き合わせた手動確認では、同じ意味変化は見つからなかった。
これは同じ作業者による小規模・非盲検の確認で、独立した人間の判定や任意の題材への保証ではない。

不合格の内訳には表現検査の限界もある。例えば、
「原稿の受渡しは担当者が行い」は正しい意味だが、指定した「担当者が受け渡」というアンカーに一致しない。
「録音は保存しませんし、名簿は公開しません」も、目視では両方の禁止を保持する。
この確認を理由に、凍結した自動合否の数字を書き換えてはいない。

候補には3件の常体の語尾が残った。
「確保されるわけではない」「含めない」「認めない」で、内容の意味変化とは区別する。
既存の安全な語尾補正で通った件数は、モデルが直接通った件数と別に集計する。

## 8人討論の実走

架空の傘相談では、8人が22件のモデル主張を出し、意見をコードで補完した件数は0。
公開22発言がWeight本文で表示され、hard gateはpassした。114.7秒、12 model calls、
本文生成は4 calls、cacheは18 hits。初期主張8人分のrawはAdapterなしの同条件実走と完全一致した。
この回は不確実性の確認へ意見が揃い、対立の再投票は発生しなかった。

そのため、全員が両案を選べるSwift/Rustの架空の設計会議も実走した。
15 eventで対案を交換した後、8人のすり合わせ投票がSwift案へ揃い、1 roundで終了した。
8人分の初期raw、8票分の投票rawはAdapterなしと完全一致した。
ただし、1件の未許可D番号と1件の本文fallbackがあり、hard gateはfail。
入力D06は安全性の優劣が未実測と明記するが、Baseの理由文には「安全性確保」という付け足しもあった。
JSON形式や投票の一致を、全ての理由文の事実性の保証とは扱わない。

特に、提案「将来の移植に備える」を「備えています」に変える本文が出た。
現在進行形への変化を検査で拒否し、Adapterが本文生成に失敗した場合の代替表示は
凍結したclaimから作るよう修正した。代替表示はモデル成功には数えない。
本文原文・投票原文・失格理由・型修復の履歴は監査rootへ保存した。
修正後の同条件実走は165.5秒、26 calls。公開文の実行中表現は0件に抑えたが、
15 event中7件が`frozen_claim_fallback`で、公開23発言中Weight本文は16件。
1件のD番号失格も残るため、hard gateはfailのまま。
安全な代替表示で完走したことを、Weightの未解決点が直ったという意味には使わない。

確認できた会話抜粋（本文はモデル生成、導入句はコード合成、記録した語尾補正を含む）:

```text
仮説構築者: 降り出す時刻が分からないので短時間でも濡れないとは言えません。
批判的設計者: 私も同じ見方です。降り出す時刻が分からないので短時間でも濡れないとは言えません。
実証監査者: そこは同意します。降り出す時刻が分からないので短時間でも濡れないとは言えません。
資源・制約設計者: 雨が降る可能性を考えて傘を持って出ます。
```

最初の傘実走では、Baseが裸のJSON配列を返し、受取側がclaims objectを期待したため全員0件になった。
「claims配列のみ」という指示をobjectとして明記し、話者の意見を補完せずに再実行した。

## 検査コードの修正

共有の否定検査を修正した。複数の制限は全て保持する必要があり、一つだけ残した文は通さない。
読点や句点を越えて、別の節の「ません」を隣の動作の否定に流用しない。
「全面置換には使わない」のように同じ制限を二つの語で表す場合は、重複して数えない。
「公開サンプル」のような名詞を、公開という動作の禁止と誤認しない。

この処理は語形と短い周辺文字列を使う近似で、日本語の意味全体を判定するパーサではない。
役割・対象・数値・条件の保持は、問題別のアンカーと全文の確認も使って判断する。
53テストで新しい反例と既存の正しい言い換えを確認した。

## 続く改善点

新しい16問での条件保持は改善したが、別題材の現在進行形化が残る。
次の学習では別の教材で時制・確実性の保持を強化し、新しい最終検証を固定する。
今回見た16問や言語選定の返答を、そのまま正解として次のtrainへ混ぜない。
会話の本文cacheによる同文反復も残っており、全ての話者が独自の文体を生成したとは言えない。

候補の判断境界は [研究用記録](../promotions/qwen3.5-4b-claim-body-v2-mlp-step48.json) に保存する。
