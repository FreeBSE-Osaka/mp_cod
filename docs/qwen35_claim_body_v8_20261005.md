# Qwen3.5 Claim Body v8 対照教材と学習検証

## 検証状況

v7で残った包含・除外の反転、試す／試みるの活用と時制、確認状態、修飾節の意味保持を、
新しい対照教材で改善する。Qwen3.5-4Bの同じ本文Adapterを通常・補助入力へ使い、旧Weightへの振分けを行わない。
192ステップを2645.276秒で正常完走し、MLX報告peak memoryは7.544GBだった。
4つのcheckpointを保存・SHA照合し、開発用の実生成からstep144を最終問題の生成前に選定・固定した。
新規16問は通常入力が親12/16から16/16、補助入力が13/16から15/16へ改善した。
旧131例は通常125/131で親と同点、補助123/131で親122/131から1件増えた。
ただし補助入力の包含・除外の反転、両入力の個別後退が残り、全面非回帰は未達。
8人実討論は親・候補とも本文23/23・代替0を維持したが、Baseの根拠誤読が残り、討論全体は不合格。
今回の学習・選定・最終比較は完了したが、General CoD全体の目標は未達である。
研究HOLDを維持し、既定Weightの置換やWeight公開は行わない。

## 教材と入力契約

新規は製本・陶器・織物・補修・鋳造・水槽の学習48件、折紙・彫刻の開発8件、
星見・蝋燭・組立・園芸の最終16件。いずれも架空の手書き教材である。
同じ対象を「含める／含めない」、行為を「試す／試している」「試みる／試みている」、
効果を「未確認／確認した」で対比する。複数対象の一方だけを除外する例も含む。
逆転・欠落・不正活用・確認状態変化・修飾節の主述化を誤文として用意した。

新規72件の正解は全て検査に合格し、誤文は全て不合格だった。
ただし固定アンカーによる検査も含むため、共通guardだけが全誤文の意味を理解したという主張ではない。
v7の学習48件だけを復習し、以前の開発／最終問題の答え、モデルの誤文や反省文を新しい学習正解へ戻していない。
train/valid/testはtopicで分離し、過去corpusとの完全一致も検査した。

学習96件を8話者へ展開した768組と、既存v3のtrain復習512組で、原文・話者組は1,280。
通常・補助入力の同じ正解の対で2,560表現となる。独立した2,560問題とは数えない。
validは566表現、testは1,014表現。実MLXのChatDatasetで全4,140表現を確認した。
入力prefixは思考なしの推論と一致し、学習対象はbodies JSONから始まる。
最大tokenはtrain330・valid322・test329で、設定448以内。

入力systemはv7と同じで変更しない。
補助情報は原文の明示kindと数量比較だけで、正解・アンカーは渡さない。
Baseの判断・証拠・投票へ本文Adapterを適用しない構成も維持する。

## 学習前の開発比較

新しいdev8を親v7 step256で生成した結果は、通常7/8・補助7/8。
両方とも「折り順の変更を試みている」が「試みました」になり不合格だった。
包含と除外、異なる対象の混合、修飾節、確認済み状態はこの8問では保持した。
新しい8問だけの結果を、旧集合や一般性能の成功と扱わない。

## 学習と事前選定規則

親v7 step256から、最後4層のmlp.down_proj、rank4、scale8、batch1、learning rate5e-6で192ステップを学習した。
gradient checkpoint有効、seed20261005。Baseと親のSHAを学習前に確認した。
48・96・144・192を同じdev8・二入力で評価し、合計の重大違反が少ない候補、直接合格が多い候補、
同点なら早いstepという順序で選ぶ。最終生成前に選定を保存し、最終問題を見て選び直さない。
教材と継続親の両方が変わる実験であり、各変更の独立した因果効果までは断定しない。

## 必須の最終検証

開発用の通常／補助入力は、step48と96が7/8・8/8、step144が8/8・8/8、step192が7/8・7/8だった。
step48と96の通常入力には包含文の言い換えによる固定アンカー不一致があり、
step192には両入力で「試みている→試みました」の再発があった。
重大違反・直接合格・早いstepの順序で144を選び、`selection.json`へ保存してから最終生成を始めた。
validation lossは開始0.068、48で0.168、96で0.149、144で0.054、192で0.104。
lossや最終ステップだけで採用せず、開発用16/16を一般性能の証明とは扱わない。

候補を固定してから、新規16問を両入力で親と比較した。
旧131例はv7の最終16例と、v6・v5・確認済み・行為効果・時制・利用条件・初期・legacyの115例を含む。
原文・正解・アンカーは変更せず、合格数だけでなく、親が通った各例の後退も検査する。
直近のv7と従来v3の両方を対照にし、失敗した集合を除外しない。
Adapter着脱probeと8人実討論で、本文の直接生成・代替文・Base判断の分離を区別して確認する。

v7で残ったBaseのD05/D06解釈の誤り、話者間の似た表現、自由な自然討論の未達点は引き続き対象である。
rendererの点数が上がっても、元のGeneral CoD全体の目標を完了としない。
修復や代替文をWeightの直接成功へ加点しない。

## 新規16問の最終比較

新規16問のstrict JSONは全4条件で16/16だった。候補の補助入力には
「苗の並べ方の変更を試みる」が「苗の並べ方を変更します」になる1件が残る。
通常入力では「試みます」を保持したが、補助入力の欠落を相殺して全問成功とは扱わない。
語尾補正・代替文を直接成功に加えていない。
新規・開発用の保存raw144件を再採点して一致し、モデル入力に正解・アンカーを渡していないことも照合した。
Adapterを取り外した前後でBaseのrawは一致したが、これは1問の決定論的本文probeに限る。

元v3と親v7の対照は、元の保存rawを再利用した。原文・話者・入力全文・WeightのSHAを照合し、
現在の同じguardで再採点した結果であり、この実験で再生成した親baselineではない。
候補は同じstep144を両入力で新しく生成し、元raw・固定アンカーを変えていない。
開発・新規・全回帰の799出力を再採点し、保存スコア・入力との一致を確認した。

通常入力は直近の親が通った1例、補助入力も同じ入力の親が通った1例が不合格となった。
該当例は「負担が減ったかは未確認」に対する「かどうかは未確認」「かについては未確認」で、
固定表現との不一致を全て意味反転と呼ばない。ただし凍結基準を緩めて加点もしない。
通常入力は元v3の合格を全て保持し、6例を改善した。
補助入力は元v3の合格2例を失い、親v7通常との比較では3例を失った。
合計が増えても、個別後退を相殺して全面非回帰の成功とはしない。

特に「売上は含めない→含めます」は補助入力で再発した。共通guardは拒否しているが、Weightで直ったとは扱わない。
「試んでいます」は正常な「試みています」へ修正できた一方、試す／試みるの言い換え不一致も残った。
以前の駐輪札の例は両入力で進行形が過去へ変わっており、既に不合格だった例の意味悪化も記録する。
親が不合格だったから無視してよいとはしない。

## 8人実討論の実測

同じ台帳・8人格・temperature0・seed20261005・最大24event・2round・話者別cacheで、
親v7と候補v8の両方を補助入力で各1回実走した。元のv3対照の再実走ではない。
両方とも15eventの対案交換、1roundのすり合わせまで完走した。

| 実測 | 親v7 | v8 step144 |
|---|---:|---:|
| 実行時間 | 316.206秒 | 325.414秒 |
| model calls | 33 | 33 |
| 公開本文のWeight生成 | 23/23 | 23/23 |
| 凍結claimからの代替 | 0 | 0 |
| 語尾補正とschema修復 | 0 | 0 |
| 失格claim | 1 | 1 |
| whole discussion hard gate | fail | fail |

独立8人と投票8人のraw、修復raw、最終選択は一致した。全判断呼出しのAdapterはNoneで、
本文入力のkind・数量補助情報は原文由来であることを照合した。
この1組での分離確認であり、任意の将来判断への非回帰証明ではない。
対案・賛同の前置きはコード合成で、本文だけがWeight生成である。
時間は他アプリ負荷にも影響されるため、今回の単発値から速度改善を主張しない。

BaseはD05を「移植不要」、D06を「安全性確保」と誤解する説明が残った。
原文はWindows追加工数未算定と、速度・安全性の優劣未実測を述べている。
未許可D05を使うRUST_FIRSTは拒否したが、ID検査を通った説明が全て正しいとは扱わない。
8人の合意も事実の証明ではなく、同じBaseが共通の誤解を持つ可能性を残す。

## 非昇格理由と次の課題

新規16問は改善したが、同じAdapterで二入力の全面安定化は未達である。
補助入力の売上除外の反転、両入力の過去化、試行意図の欠落、凍結アンカーへの不一致が残る。
通常入力だけを選んで全体成功としたり、失敗を別Weightへ振り分けたりはしない。
Baseの根拠解釈と自由な自然討論の未達も引き続き対象で、Goalを完了としていない。

次は同じ教材を増やすだけでなく、失敗の入力依存・学習対象層・文中の時制検査を切り分ける。
これは次の実験候補で、原因が特定済みという主張ではない。
今回の最終問題の答えを新しい学習正解へ戻さず、元rawと凍結評価を維持する。
既定置換・Weight公開は行わず、研究Weightを保持する。

## 再現と保存先

```sh
<mlx-python> tools/general_body_training.py build \
  --curated data/general_body_qwen35_v8/curated.json \
  --renderer-system-file configs/claim-body-qwen35-4b-v7-system.txt \
  --plain-system-file configs/claim-body-qwen35-4b-v5-system.txt \
  --constraint-hints --rehearsal /path/to/v3/mlx_shared \
  --out /path/to/new-dataset

<mlx-python> tools/general_body_training.py train \
  --model /path/to/Qwen3.5-4B-4bit --data /path/to/new-dataset \
  --config configs/claim-body-qwen35-4b-v8.yaml \
  --parent-adapter /path/to/v7/step256/adapters.safetensors \
  --out /path/to/new-adapter
```

TMPDIRは外付け、ネットワークはオフライン指定、容量は20GiB・2秒間隔で監視する。
これはOSやGPUの全クラッシュを防ぐ保証ではない。
