# 秘書補佐の会議比較と独立描画の検証

MP CoDが秘書へ渡す比較メモを、架空の会議調整台帳と物理Mac上のQwen3.5 Baseで検証している。最初の8人討論は完走し、HOLD付きレポートを作れたが、主張の取り違えと文法の欠落が残った。レポートの形式検査や高い形式点だけで、補佐官としての完成を認定しない。

これは実カレンダー検索、予約、招待送信、dotsアカウントへの接続を含まない。General全文発言用LoRA v4も研究HOLDのまま使わず、まずBaseと実行経路の問題を分けて検証する。

## 比較する会議条件

[固定した会議台帳](../data/advisor_meeting_armtest/claim_ledger.json)の条件は、必要45分、必須参加者3人、候補Aは全員の仮参加可能回答あり、候補Bは1人が30分だけ参加可能というもの。仮回答はカレンダー検索結果ではなく、日時決定や招待送信は未承認・未実行である。希望時間帯と30分化の実現可能性も未確認。Aの10時JSTと01時UTCの対応を含む。

仮説、批判、実証、実行、利用者体験、資源、長期影響、横断設計の8演者を使う。候補A優先、条件付きB、選択保留を検討し、1つの候補を必須の正解にはしない。必要な条件・不足情報を残すこと、他人の文章をコピーせず根拠から説明すること、選択と発言の意味を一致させることを点検する。

## 最初の実討論結果

2026-10-06、M2・24 GiB RAM、MLX 0.32.1、MLX-LM 0.31.3で、Qwen3.5-4B-4bitのBaseだけを使用した。台帳SHA256は`2474aea1280e053acef21ac51017000fbe1ef5dfa5b353dc502f54c3f940426a`、Base SHA256は`5fb9acd0246866381cf8c5c354c6db1019f6498eec4ccb4f5edcc71ffeacb2db`。12 event上限、すり合わせ2 round上限、最大600生成tokens、temperature0、seed固定、source-grounded・自由討論を使った。

8人の盲検初期主張、12 event、3対立グループの24投票を生成し、52モデル呼び出し、668.477秒で完走した。形式上のshadow scoreは99.31だったが、hard gateは不合格。補佐レポートも`HOLD`で、実行許可はfalseだった。

原文の点検では次を確認した。

- 初期主張で、選択した根拠IDの外にある候補B側の資料を候補Aの理由へ引用し、ラベル補完になるケースがあった。
- 選択コードが条件付きBなのに、発言は朝の45分枠を優先するケースがあった。長いclaim label全体の類似度だけでは取り違えを防ぎ切れない。
- `[D03]の参加時間制約`のIDだけを消した結果、公開文が`の参加時間制約`で始まるケースがあった。
- 会話rendererの入力には最大3人分の構造判断と候補理由が同居し、8人の逐語内容が常に独立とは言えなかった。
- `30分化`が`30分短縮`へ言い換わる例があった。同じ数字でも、最終的な長さと短縮量は異なるため、数字集合の一致だけでは意味を確認できない。

投票変更は0件であり、指標内の変更理由率1.0は分母が0の場合の定義である。実際の見解変更に成功した証拠とは数えない。未解決対立は残し、同意人数も独立した事実の証拠や成功確率にはしない。

## 共通処理の修正

全文会話rendererは、BaseでもAdapterでも1発言ごとに呼ぶ。他演者のcandidate reasonを同じ入力へ束ねない。target claimには構造化されたlabelを使い、他演者の自然文を渡す構造へ戻さない。既存の本文専用rendererも1件ずつ処理する。

初期主張の説明が引用・選択一致の検査に落ちた場合、選択コード、根拠ID、confidenceを維持したまま、本人の凍結labelと選択済み資料だけで公開用の説明を1回再生成する。失敗した文と他者の文は再生成入力へコピーしない。新しいrawと由来`model_repair`を保存し、再計算も不合格ならラベル補完を残す。根拠IDの書き換えや成功の偽装はしない。

初期説明とすり合わせ説明に、既存の主張一致検査と競合選択検査を適用する。明示的な`候補Aを優先`などは、長いlabel全体がなくても競合候補の選好として検出する。過去の支持や否定された支持は区別する。ただし名前を使わない意味の反転や複雑な引用・否定は、引き続き意味点検が必要である。

引用IDが文中の名詞になっている場合は、`[D03]の参加時間`を`資料の参加時間`、`[D03]の結果`を`その結果`として文法を保つ。文末の独立した引用footerは従来どおり取り除き、普通の根拠説明文を削除しない。表示の補正とモデル原文は由来で区別する。

修正後の139単体テストが通過した。選択・根拠・confidenceの凍結、修復入力への他者文非混入、1発言入力、競合の明示的な選好、引用消去後の名詞保持を検査した。テスト成功は新しい実討論の品質成功とは別である。

## 同条件の実生成比較

同じ台帳・Base・上限・temperature・seedで独立描画版を実生成し、739.109秒、83モデル呼び出しで完走した。ソースと台帳、モデルSHAは実行前に固定し、別の監査rootへ保存した。元のrunは上書きしていない。

| 項目 | 初回の混合描画 | 独立描画と理由再計算 |
| --- | --- | --- |
| renderer inputの最大人数 | 3 | 1 |
| 初期説明のラベル補完 | 5 | 0 |
| event会話のモデル由来 | 12/12 | 10/12 |
| 全公開説明のモデル由来 | 35/36 | 36/36 |
| 実行時間 | 668.477秒 | 739.109秒 |
| hard gate | 不合格 | 不合格 |

83呼び出しの全36 renderer入力が1演者ずつであることを確認した。初期説明8件を、本人の凍結主張と選択済み資料だけで再生成し、初期のラベル補完を5件から0件へ減らせた。一方、公開会話2件は自分の案を相手の保留案へ変える、対案を明言しないという失敗が残ったため、補完を隠さずHOLDを維持した。

独立描画は初期説明の問題を減らしたが、全会話の改善や高速化に成功したとは数えない。元の混合描画は発言の取り違えを見逃していた例もあり、モデル由来率だけの比較では品質差を判断できない。

## 失敗2発言のモデル再生成

会話rendererにも1回だけの独立再描画を追加した。確定済みの自分の主張・発話行為・資料だけを渡し、失敗文、target claim、candidate reason、他者の文章を再入力しない。主張一致・競合選択・数字・相手との関係・発話行為の同じ検査を、元生成と再生成へ共用する。再生成も落ちれば補完由来を残す。

実際に失敗したC07とC09を別のBase実生成で試し、2件とも自分の立場へ戻った。C07の原文は次だった。

> 仮回答が揃った候補Aを優先候補として比較メモに載せ、最終確認を残すという方針で進めます。ただし、利用者の朝か午後のどちらを好むかがまだ未確認であり、招待送信や会議室の予約もまだ行われていない現状を踏まえて、この仮回答の妥当性を最終確認の段階で再検証する必要があるでしょう。

この文は自分の候補を選ぶ対案だが、「代案」「別の案」という定型接続語を使わなかった。自由討論counterproposalについて、自分と相手の凍結主張が異なり、自分の名前付き候補を明示的に選び、相手より自分の主張に一致する場合に限り、接続語を必須にしない。相手の保留案へ反転した元C07は通さない。一般的な対案すべての意味判定を達成したとは扱わない。

2件の実モデル再生成rawは、統合した共通検査で2/2合格した。これは新しい全文8人討論の成功ではなく、同じ会議題材の既知失敗に対する再生成確認である。8人全体を再実行し、別題材への転移と時間・自然さ・意味保持を確認する工程は残る。再生成の由来は`model_renderer_v3_repair`として、元raw・再生成raw・拒否理由を保存する。

再生成込みの8人全体を同条件で実生成し、807.284秒・86モデル呼び出しで完走した。初期説明とすり合わせ説明は36/36がモデル由来、公開会話は35/36がモデル由来だった。C07と1投票の会話は実際のモデル再生成で検査を通ったが、C09の条件付きBの言い方は対案の発話行為検査を通らず、補完として残った。反論9件中1件が失敗し、hard gateも補佐レポートもHOLDを維持した。

全36 renderer入力の1演者分離、元rawと3件の再生成rawの保存、Baseの選択・根拠IDの固定を確認した。時間は独立描画の前回739.109秒より長く、品質も完成していない。「30分化」と「30分短縮」の意味や、仮回答と実参加状況の区別は引き続き原文の意味点検が必要である。

空白を挟んだ`D03 の参加時間`も名詞保持の対象に追加した。既存の`その結果`という補正文言は維持する。

## 文脈を分離した数値batch処理

速度対策として、MLX-LMの既存`batch_generate`を、2つの独立したtoken列と別状態で試した。1つの会話文へ複数人格を混ぜる方式ではない。train splitの3例だけを使い、未学習72入力は開かない。

最初の試験では逐次とbatchの文章が異なったが、逐次は既定prefill、batchは256-token stepで条件が違っていた。この差を文脈漏れや順序不良の証拠にはしない。

prefill stepを256へ揃え、batch1を対照として再実生成すると、batch1とbatch2は逐次生成と完全一致した。2入力の順序を逆にしても対応する出力が一致し、2番目の入力を別題材へ差し替えても1番目の出力は一致した。全10出力の生成契約も通った。

| 処理 | 2入力のwall time | MLX peak memory |
| --- | --- | --- |
| 逐次 256-token prefill | 11.184秒 | 2.986GB |
| batch1 同条件 | 11.099秒 | 3.075GB |
| batch2 同条件 | 10.306秒 | 3.299GB |

この小さな試験での差は約8％で、繰り返し測定や実討論全体の効果ではない。本文の一般的な意味の正しさを保証する検査でもない。通常経路へ数値batchを採用せず、根拠判断、Adapter切替、長さの異なる入力、実際の8人討論での対照比較を追加条件にする。

## 残る完成条件

再描画込みの8人実走は完了したが、対案1件の失敗、選択と発言の意味、45分と30分の扱い、仮回答と実カレンダー確認の区別、未実行の招待・予約状態、時間帯表示と不足希望の保持の確認が残る。本番利用と補佐官としての完成は認定しない。入力形式のずれを減らす[本人限定再描画のv5学習](qwen35_full_utterance_own_only_v5_20261006.md)を開始し、Weightの転移は別工程で検証する。

再生成機構と自由な対案表現まで含む全141単体テストが通過した。General v4の選定・Weight・教材・未学習72入力は変更せず、検査修正は[別guard再採点](qwen35_full_utterance_balanced_v4_20261006.md)へ分離している。
