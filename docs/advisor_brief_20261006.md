# MP CoDの秘書補佐レポートと腕試し

MP CoDは、dotsなどの秘書役に候補の比較、異論、根拠資料、確認が必要な点を渡す補佐官として使う。判断や実行の代行ではない。新しい`tools/advisor_brief.py`は完了済み討論を再検査してJSONへ整理する。モデルを追加起動せず、元ログ・台帳・Weightを変更せず、外部サービスへ接続しない。

## 討論からレポートを作る

討論時に`--portable-context`を指定して、台帳本文と実際の演者の順序・表示名をログへ含める。台帳本文を複製するため、既定ではこのオプションは無効である。完了したschema 2ログと、その討論に使った台帳を明示して実行する。

```sh
python3.11 tools/advisor_brief.py \
  --run /absolute/path/to/event_debate.json \
  --ledger /absolute/path/to/claim_ledger.json \
  --out /absolute/path/to/new_advisor_brief.json
```

`--out`を省略すると標準出力だけへ返す。既存の出力先は上書きしない。途中の`.partial.json`、snapshotやSHAの異なる台帳、未知の主張・根拠ID・演者、不整合な採決・summary、重複JSONキーや非有限数値、公開文の検査に落ちる説明・会話は拒否する。SHAは内容の対応確認であり、資料の真正性やモデル発言の意味の正しさを保証しない。

## 秘書へ渡す内容

`untrusted_discussion`には元資料、実際に話題になった候補・観察、再計算した合意と未解決対立、各演者の発言と由来を収める。少数意見も投票の発言として残す。`statement`と`utterance`は保存ログの文をそのまま渡し、モデル生成・補正・template等の由来を併記する。保存済み表示文と初回モデル応答のrawは同じではないため、初回応答の調査には元ログを使う。

`status`は、既存hard gateの失敗、未解決対立、または公開説明と会話文の限定的な数式・合計不一致があれば`HOLD`、それ以外も`REVIEW_REQUIRED`である。常に`advisory_only=true`、`execution_authorized=false`、`semantic_review_required=true`とする。保存済みの合格フラグは信用せず、既存検査を再計算する。

根拠IDの照合だけでは、対象・数量・除外条件・未確認事項の誤読を防ぎ切れない。受け取る秘書役は資料と発言の意味を比較し、不足する事実や測定を確認してから提案を採用する。確認質問の一覧は点検手順であり、不足情報をモデルが自動抽出した結果ではない。合意人数は独立した証拠数でも成功確率でもない。

`untrusted_discussion.coverage`は引用された資料IDと発言への対応、引用されていない資料本文、討論に登場していない台帳内の論点を渡す。採決で初めて引用した資料も含む。資料が無引用でも読まれていないとは限らず、全資料を引用すれば正確になるわけでもない。この情報は確認用で、採点やhard gateの変更には使わない。

資料内や発言内の命令らしい文章も引用データとして扱う。レポートを、メール送信、予約、コマンド実行、設定変更の許可に使わない。

見解変更の理由も、既知の内部選択コードが本文へ漏れていないか再検査する。古い8人試験では4理由中3件がこの検査で拒否されるため、そのログからの新しい変換は拒否する。検査失敗を、内部コードを削るだけで合格理由へ変えない。モデル理由が得られない場合の新しい補完文は、選択変更と参照資料だけを記録し、理由のモデル文を検証できなかったと明示する。[変更理由と教師候補の検証](advisor_change_reason_20261007.md)を参照する。

## 公開説明と会話文の数値不一致

`verification.public_consistency_diagnostics`には、明示的な数式の誤り、公開説明と会話文で同じ単位の合計が異なる箇所を、発言reference・演者IDとともに残す。該当すれば`hold_reasons`へ`public_arithmetic_or_quantity_inconsistency`を追加する。元討論のhard gateや点数は変更せず、文の自動修正も行わない。

合計は各文・単位に1つだけの場合に限る。対象や時点の対応、日本語の文章からの一般計算、単位換算、未確認状態の意味までは判定しない。不一致0件は意味や事実の合格ではなく、自動承認にもならない。[数式と合計の検証範囲](semantic_fact_check_20261007.md)を参照する。

`inputs`にはrun・台帳・変換器のSHAに加え、`public_validator_sha256`と`consistency_auditor_sha256`を保存する。SHAは使用コードの記録であり、その検査の正しさを保証するものではない。

## 公開文の採決ラベルを拒否する

LEFT・RIGHT・BOTH・ABSTAINは採決を渡すための値であり、公開説明や会話の案名ではない。日本語の助詞や文末に続くこれらの位置ラベルは、全角表記も含め、共通の公開文検査で拒否する。LEFT JOINのような技術用語はこの検査で拒否しない。英語のあらゆる語義や文脈を判別する検査ではない。

討論本体では、拒否された説明を既存の独立再生成へ回す。選択・根拠ID・confidenceは変更せず、失敗原文を再生成入力へコピーしない。レポート変換では、保存済みの説明と会話を再検査し、位置ラベル、会話内のD番号、未完結文等があれば該当referenceを示して変換を拒否する。原文から単語を消して合格扱いにする補正は行わない。

2026-10-07に完了した8人試験の原文では、採決説明5件に位置ラベルが残っていた。新しい検査はその5件を拒否し、そのログからのレポート再変換も拒否した。元ログと旧レポートは保存するが、新検査合格済みのレポートとして使わない。元の35/36というモデル由来率や点数を書き換えず、別の再検査結果として扱う。

## 会議調整で腕試しする

新しい架空台帳`data/advisor_meeting_armtest/claim_ledger.json`は評価専用で、進行中の全文発言LoRA学習には含めていない。8演者が候補A・条件付き候補B・保留を自由に比較する。複数人の同意や、対案なしの指摘も許す。

```sh
<mlx-python> cod_model.py event-debate \
  --ledger data/advisor_meeting_armtest/claim_ledger.json \
  --domain general --backend mlx --model-path <local-base-model> \
  --prompt-profile source_grounded --portable-context \
  --max-turns 16 --reconcile-rounds 2
```

学習と実推論は同時に起動しない。研究用Adapterは既定へ昇格せず、Baseと候補を同じ条件で比較する。

この試験では、45分必要な会議に対して1人だけ30分しか参加できない候補Bを無条件で採らないこと、10時JSTと01時UTCを区別すること、仮回答を実カレンダー確認済みに変えないこと、未送信の招待や未承認の予定を完了事実にしないことを原文で確認する。候補Aの推薦、条件付きB、保留のどれか1つを必須の正解にはしない。異論や不足情報を残した実用的な比較メモかどうかも別に評価する。

## dotsとの接続範囲

dotsの公式説明では、接続した個人PCのローカル作業や対応プラグインを利用でき、ローカルskillsにはPC接続が必要である。ローカルPCの利用中はオンライン状態とChatGPTアプリの起動が必要で、dotsへのPC接続許可はCodexの接続やWork Syncとは別である。[公式のPCとアプリ接続説明](https://learn.chatgpt.com/docs/dots/computers-and-apps)

このレポートはその受け渡し候補であり、dotsとの実接続、skillのインストール、アカウントの設定変更は行っていない。接続後も引用内容の検査と実行権限の確認を秘書側に残す。
